## 0. 先搞懂这几个词（基础差也能看懂）

### 0.1 什么是"阶跃响应"
你站在电机旁边，电机静止。某一瞬间你突然给它下命令："**立刻转到 100rpm**"——
目标值从 0 **一步跳到** 100，像楼梯的台阶一样，这叫**阶跃输入**。

然后你把电机"实际速度"随时间的变化画成曲线，这条曲线叫**阶跃响应曲线**。
所有分析指标都从这条曲线上量出来：

```
 转速(rpm)
  120 ┤        ╭─╮            ← 冲过头了（峰值）
  100 ┤──────╭─╯ ╰─────────   ← 目标值 100
      │     ╱                  ↑ 上升（响应）
    0 ┼────╱────────────────────────── 时间
       阶跃开始
```

三个指标：

| 指标 | 大白话 | 怎么算 |
|---|---|---|
| **超调量 σ%** | 冲过目标多少 | `(峰值 - 目标值) / 目标值 × 100%`（例：冲到 120，目标 100 → 超调 20%） |
| **响应时间** | 多久"到位" | 从阶跃开始，到**进入并稳定在目标 ±2%（或 ±5%）误差带**的时间 |
| **稳态误差** | 停下后差多少 | 稳定后 `|实际值 - 目标值|`（例：稳定在 98rpm → 稳态误差 2rpm） |

> 一句话口诀：**超调看"冲多高"，响应时间看"多快稳"，稳态误差看"稳在哪"。**

### 0.2 PID 是什么（一句话版）
- **P（比例）**：差得越多，推得越狠 → **主力**，但单独用会留下一点"推不到底"的误差（静差）。
- **I（积分）**：把"长久累积的小误差"攒起来慢慢补 → **消除稳态误差**，但攒太多会冲过头（超调）。
- **D（微分）**：看误差变化的**趋势**，快到了就提前刹车 → **抑制超调、加阻尼**，但会放大噪声。

```
out = Kp·e + Ki·Σe·dt + Kd·(e - e_last)/dt        e = 目标 - 实际
```

### 0.3 什么是"速度环 / 位置环 / 双环"
- **速度环**：我的目标是"**转多快**"，PID 输入是 (目标速度 − 实际速度)，输出是**电压**。
- **位置环**：我的目标是"**转到哪个角度**"，PID 输入是 (目标角度 − 实际角度)。
- **单环位置控制**：角度误差 → 直接算电压。**问题**：误差大时输出巨大 → 猛冲、超调、震荡；且无法限制速度，容易撞坏。
- **双环（串级）**：**外环位置**的输出不再直接是电压，而是"**你应该以多快的速度过去**"（速度目标，并且**限幅**）；**内环速度**再把这个速度目标变成电压。

```
 目标角度 ──► [位置环 PID] ──► 速度目标(限幅) ──► [速度环 PID] ──► 电压 ──► 电机
       ▲                                                              │
       └────────────────── 实际角度 ◄── 累计 ◄── CAN 反馈 ─────────────┘
```

**为什么必须双环**：
1. 内环（速度）响应快，能**主动刹车**，外环只要慢慢给目标 → 又快又不冲；
2. 速度目标**限幅**，等于给电机加了"最高限速"，机械安全；
3. 外界扰动（手掰一下）先被内环吃掉，外环几乎不受影响；
4. 调参可以**分层调**：先关掉外环调好内环速度环，再调外环（否则两个环互相打架，怎么调都不对）。

### 0.4 "PID 代码库 / 实例化"是什么意思
不要给每个环写一遍 PID 公式，而是写**一份**通用的 PID 代码，里面定义一个"PID 控制器"的**模板（结构体）**，
用的时候**创建几个实例**：速度环一个、位置环一个，将来云台 pitch、yaw 各一个。

```
PID_t  pid_speed;   // 速度环实例
PID_t  pid_angle;   // 位置环实例

PID_Init(&pid_speed, 5.0f, 0.2f, 0.0f, ...);   // 各实例参数独立
out = PID_Calc(&pid_speed, target_rpm, now_rpm);  // 给目标和实际，拿输出
```

改 `pid_speed.Kp` 只影响速度环，不影响位置环——这就是"对象/实例"的意义。

## 1. 硬件准备与安全（先做，别急着写代码）

- [ ] 云台板 ×1，STLink/J-Link 下载器 ×1
- [ ] GM6020 ×1，**24V 电源**（XT30），**CAN 信号线**
- [ ] USB-TTL ×1（接 VOFA 打曲线，用 USART5：PC12=TX，PD2=RX）
- [ ] 万用表、螺丝（**电机必须固定住！** 大扭矩会自己飞出去）

⚠️ **安全三条**：
1. 24V **先断电接线**，确认极性再上电（反接直接烧）；
2. 电机输出轴**必须固定**，且**不要装负载/桨叶**做首次测试；
3. 第一次给的电压**从小到大**（±3000 起步，别一上来 ±25000）。

## 2. 软件总体架构（沿用你阶段一的"出色框架"）

```
【中断层】CAN1_RX0_IRQHandler ──► 队列(8) ──► Task_MotorCtrl（1ms，vTaskDelayUntil）
                                                 │ 解析反馈→更新电机状态
                                                 │ 双环 PID 计算
                                                 ▼
                                          HAL_CAN_AddTxMessage（控制帧 0x1FF/0x2FF）
【中断层】USART5 IDLE+DMA ─► 队列(3) ─► Task_Cmd（解析 "kp=1.2" 等调参命令）
                                      └► Task_Log（5ms，JustFloat 打 target/current/out）
【保护】反馈超时(>100ms) 或 遥控失联 → 输出 0，PID 积分清零
```

任务一览（**建议先 3~4 个任务，后可加遥控任务**）：

| 任务 | 周期 | 职责 |
|---|---|---|
| Task_MotorCtrl | **1ms**（vTaskDelayUntil 绝对周期） | 读反馈 → 双环 PID → 发控制帧 + 超时保护 |
| Task_Cmd | 事件驱动 | 串口命令：设目标 / 改 PID 参数 / 打印曲线开关 |
| Task_Log | **5ms** | VOFA JustFloat 打曲线（target / current / out） |
| Task_Breath（可选） | — | 继承阶段一，验证框架可复用 |

> 控制周期为什么是 1ms？GM6020 反馈就是 1kHz，控制周期与反馈同频最稳；
> 太快（0.2ms）会重复用同一帧反馈，太慢（10ms）会抖。

## 3. 分步实施（每步都有验收标准）

### Step 0 — 建立基础工程（CubeMX）
**做**：F405RGT6 新建工程 → 配时钟（168MHz，APB1=42MHz）→ CAN1（PA11/PA12）→ USART5（PC12/PD2）+ DMA → FreeRTOS → SWD。
**验收**：`printf` 能打印（VOFA 文本窗口可见）。
**坑**：换芯片后 SystemClock_Config 与引脚全变，**不要直接拷 F407 工程**。

### Step 1 — CAN 1Mbps 调通（不发电机指令）
**做**：CAN 初始化（Prescaler=3, BS1=10, BS2=3, SJW=1 → 1Mbps），过滤器掩码模式收 0x200~0x20F。
先用**环回模式（Loopback）**自测：发一帧自己收，验证"软件通"；
再切正常模式接电机。
**验收**：环回能收到自己发的帧；正常模式下 CAN->ESR 无持续 LEC 错误。
**坑**：单节点无 ACK 会 Bus-Off（属正常）；总线两端必须有 120Ω（共 60Ω）。

### Step 2 — 辨识并修改电机 ID（验收项 ③）
**做**：上电，**数绿灯每秒闪几次 = 当前 ID**（如闪 2 次 = ID2 → 反馈帧 0x206）。
断电 → 拨 Bit0~2 → 上电再数，确认改变。
**验收**：能说出"拨码 → ID → 反馈标识符"的对应关系（见理论笔记 2.3）。
**坑**：橙灯每秒闪 2 次 = 总线上有重复 ID。

### Step 3 — 读取电机反馈（验收项 ⑤）
**做**：在 CAN 接收中断里只打包入队；任务里解析：
`angle_raw = (d[0]<<8)|d[1]`，`speed = (int16)((d[2]<<8)|d[3])`，`current`，`temp`。
**验收**：Keil **Debug → Watch** 里能看到角度随手动转动变化（0~8191 单调变化），温度约室温。
**坑**：大端字节序别搞反；`speed` 是 **int16**，要带符号。

### Step 4 — 发送控制指令让电机转（验收项 ④）
**做**：组帧 0x1FF（ID1~4）/0x2FF（ID5~7），电压值 int16 大端，1ms 周期发。
先发 **+3000**（约 12% 电压）看是否缓慢转动，再试负值和加大。
**验收**：电机按 CCW/CW 双向受控转动；**发送停止后能马上停**。
**坑**：控制帧必须**周期性持续发送**（一般 1ms 一帧），发一帧就停电机会按最后一次值继续出力——
所以**任何异常都要显式发 0**。

### Step 5 — 写 PID 代码库（模块化，验收项 ⑥）
**做**：新建 `pid.c / pid.h`（接口见下节），先写一个速度环实例跑起来。
**验收**：改 `Kp` 后电机"跟随速度"的强弱**明显变化**（证明库可用、可被实例化）。

### Step 6 — 速度环（验收项 ①）
**做**：目标速度（GM6020 建议 **60~200rpm**，⚠️ 1000rpm 做不到）→ 速度环 PID → 电压。
**验收**：速度稳定在目标附近；打印阶跃曲线。

### Step 7 — 位置环双环（验收项 ②）
**做**：外环位置（角度误差 → 速度目标，限幅 ±200rpm）→ 内环速度 → 电压。
**验收**：180° 阶跃，曲线平滑到位、超调小。

### Step 8 — 多圈角度 720°（验收项 ④）
**做**：把单圈 0~8191 的机械角度**累加成连续角度**（跨圈修正），再上电时把当前位置设为 0 起点。
**验收**：连续正转 720° 后停在正确位置（误差 <1°）。

### Step 9 — 不重新编译的调参（验收项 ③）
**做**：串口命令改参数（见第 5 节）+ Keil Live Watch 直接改全局变量。
**验收**：**一整轮调参不编译一次**，改完立刻看到曲线变化。

### Step 10 — 保护与收尾
**做**：反馈超时保护（>100ms 无新帧 → 输出 0 + 清积分）、输出限幅、上电缓启动、遥控保护接口预留。
**验收**：拔掉 CAN 线，电机**立即停止出力**（安全要求）。

## 4. PID 库设计（接口先定死，后续只加不改）

### 4.1 `pid.h` 接口（C 版，可直接用）

```c
typedef struct {
    /* 参数 */
    float Kp, Ki, Kd;
    float outMax;        /* 输出限幅（电压环 = ±25000） */
    float iMax;          /* 积分限幅（抗积分饱和）      */
    float deadband;      /* 误差死区（可选，抑制抖动）  */
    /* 状态（只读，调试看这些） */
    float target, feedback;
    float err, errLast, errSum;
    float pOut, iOut, dOut, out;
} PID_t;

void PID_Init(PID_t *pid, float kp, float ki, float kd, float outMax, float iMax);
void PID_SetParam(PID_t *pid, float kp, float ki, float kd);  /* 运行时改参数 */
void PID_Reset(PID_t *pid);                                   /* 清积分/历史 */
float PID_Calc(PID_t *pid, float target, float feedback);     /* 核心：给目标和实际，返回输出 */
```

**设计要点（加分项）**：
- **积分限幅 + 输出限幅**：防止长时间误差把积分"憋爆"（抗积分饱和）；
- **`PID_Reset`**：切换模式/保护时必须清积分，否则会突然猛冲；
- **所有状态在结构体里** → Debug 的 Watch 窗口可以直接看 `errSum`、`pOut` 分解量，调参有依据；
- **不用全局变量** → 天然支持多实例（速度环/位置环/pitch/yaw/摩擦轮）。

### 4.2 调用示例（双环）

```c
/* 1ms 周期任务里 */
float angle_now = Motor_GetContinuousAngle();      /* 连续角度（度，可多圈） */
float speed_now = Motor_GetSpeed();                /* rpm */

float speed_cmd = PID_Calc(&pid_angle, target_angle, angle_now);  /* 外环 */
speed_cmd = LIMIT(speed_cmd, -200.0f, 200.0f);                   /* 限速 */
float voltage = PID_Calc(&pid_speed, speed_cmd, speed_now);      /* 内环 */
Motor_SendVoltage(voltage);                                      /* → CAN */
```

### 4.3 C++ 混编（可选加分）
把 `PID_t` 换成 `class PID { public: float Calc(float target, float fb); ... }`，
用 `extern "C"` 包一层 C 接口给其它 .c 文件调用。
**建议**：先把 C 版跑通验收，**有余力再上 C++ 版**（Keil 下 C++ 要注意不使用动态内存 / MicroLIB 与 `new`）。

## 5. 调参方法（**不重新编译**）

### 方案 A：串口命令（推荐，最省事）
VOFA 文本窗口直接发命令，Task_Cmd 解析：

```
sp 100        → 速度目标 100rpm
ang 180       → 角度目标 180°
kp 1.5        → 改速度环 Kp（kp2/ki2/kd2 改外环）
pr            → 打印当前所有参数
```

### 方案 B：Keil Debug 的 Live Watch
Debug 全速运行 → `View → Watch → PID_t pid_speed` → **直接双击改 `Kp` 的值** → 立刻生效。
（要求变量是**全局**且未被编译器优化掉；调参期间开 `-O0`。）

### 方案 C：曲线
Task_Log 每 5ms 用 **JustFloat** 打 4 个通道：
`target`、`current`、`out`、`err` —— VOFA 里一条目标线、一条实际线，超调/响应时间一眼看出。

**调参顺序（记住，省一半时间）**：
1. 先调**内环速度环**：Kp 从小加大到"快速跟随但不过冲"，再加一点 Ki 消静差；
2. 内环调好**再开外环位置环**：Kp 决定"多快冲过去"，Kd 抑制超调，Ki 一般很小或为 0；
3. 每次只改一个参数，改完打一条阶跃曲线对比。

## 6. 验收时要能说出来的三件事

1. **CAN 为什么可靠**：差分 + 非破坏性仲裁 + CRC + ACK + 错误计数/自动重发（见理论笔记）。
2. **为什么双环**：内环限速与抗扰、外环定位；单环位置到大误差会猛冲超调（见 0.3 节）。
3. **曲线怎么分析**：超调 = 峰值越过目标的比例；响应时间 = 进入 ±2% 误差带的时间；稳态误差 = 最终差值。
   每个结论都要能指出"**是我调了哪个参数导致它变好/变差**"。
