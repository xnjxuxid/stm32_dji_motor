# 阶段三操作与接线文档（富斯 i6X + iA10B → iBus）

> 固件：`MDK-ARM\stage3\stage3.hex`（0 Error / 0 Warning）
> 协议选择：**iBus**（115200 / 8N1 / 正逻辑，一根信号线，最简单）
> 板子接口：**J8 座（GHS1.25 4P）= USART6_RX(PC7)** —— 无反相、带 3.6V 保护二极管

---

## 〇、协议与接口怎么选（当前配置：**SBUS，走 P1 座**）

| 设备 | 能输出什么 | 依据 |
|---|---|---|
| **FS-iA10B** | PWM / PPM / **i.bus** / **s.bus** | 富斯官网参数页：数据接口 = `PWM/PPM/i.bus/s.bus` |
| DJI DR16 | **DBUS**（DJI 私有，只能配 DT7 遥控器） | 硬件事实 |

**当前固件配置：SBUS → P1 座（USART2/PA3，板上 Q1 SS8050 已反相）**

```c
/* board_config.h */
#define RC_PROTOCOL  (1)   /* 1 = DBUS/SBUS(PA3/P1座)；改 0 = iBus(PC7/J8座) */
```

两个协议物理层对比（**SBUS 与 DBUS 完全一致，所以能共用一个口**）：

| | SBUS | DBUS | iBus |
|---|---|---|---|
| 波特率 | 100000 | 100000 | 115200 |
| 格式 | 8E2 | 8E2 | 8N1 |
| 电平 | **反相**（需反相器，板上已有） | **反相** | 正逻辑 |
| 帧长 | 25 字节（0x0F 头 / 0x00 尾） | 18 字节 | 32 字节（0x20 0x40 头） |

代码会**自动识别 18/25 字节帧**，所以 P1 座上插 SBUS 接收机或 DR16 都能用。

> 兜底：若你的 i6X 菜单里**找不到 S.BUS 选项**（固件版本问题），就把 `RC_PROTOCOL` 改回 `0`，
> 用 i-BUS 走 J8 座，两种固件都编译验证过（0 Error / 0 Warning）。

## 一、为什么选 iBus、为什么用 J8 座

| 协议 | 波特率 | 校验 | 电平 | 复杂度 |
|---|---|---|---|---|
| **iBus** | 115200 | 无 | **正逻辑** | ⭐ 最简单（一根线直连） |
| SBUS | 100000 | 偶校验 8E2 | 反相（要反相器） | 中 |
| DBUS(DR16) | 100000 | 偶校验 8E2 | 反相 | 中 |
| PPM | — | — | 脉冲 | 需定时器捕获 |
| PWM | — | — | 每通道一根线 | 线最多 |

**板上两个接口的区别（原理图确认）**：

| 座子 | 丝印 | 信号 | 适用协议 |
|---|---|---|---|
| **P1（RC+Servo）** | "下层DBUS，上层舵机" | 经 Q1 **SS8050 反相** → PA3 | **DBUS/SBUS**（DR16 用这个） |
| **J8（GHS1.25 4P）** | USART6 | **USART6_RX(PC7)** 直连 + 5V + GND，带 D5 3.6V 保护 | **iBus**（iA10B 用这个） |

> 反相器只适合"本来就反相的协议"（DBUS/SBUS）；iBus 是正逻辑，必须走没反相的 J8。

## 二、接线（SBUS → P1 座，3 根线）

| iA10B 的数据口（i-BUS / S.BUS） | 云台板 **P1 座（RC+Servo，下层 DBUS）** | 说明 |
|---|---|---|
| 信号 S | **DBUS 信号脚**（下层 3 针的中间/信号脚） | 经板上 Q1 SS8050 反相 → PA3 |
| + | **5V** | 接收机供电 |
| − | **GND** | **必须共地** |

P1 座丝印：**"下层DBUS，上层舵机"** —— 接**下层那一排**（DBUS），别接到上层舵机口。
针脚顺序通常为 **信号 / + / −**（以座子丝印为准，接反不会烧但收不到数据）。

> ⚠️ 这个口**已经反相**，所以只能接 **SBUS / DBUS** 这类"本来就反相"的协议；
> 正逻辑的 iBus 接这里会收不到数据。

## 二·五、iA10B 针脚速查与对码（新手必看）

### 针脚长什么样

iA10B 上所有接口都是 **3 针一排**（富斯标准顺序）：

```
   ┌───┬───┬───┐
   │ S │ + │ − │        S = 信号（Signal）
   └───┴───┴───┘        + = 电源正（VCC，4.0~8.4V，通常接 5V）
    信号  正  负         − = 地（GND）
```

> ⚠️ **以接收机外壳丝印为准**：有的批次印 `S + −`，有的印 `− + S`，
> 顺序可能反过来。拿不准就用万用表：对地量到 5V 的那根是 `+`，剩下的单根是信号 `S`。

### 接口分区

| 区域 | 丝印 | 用途 | 本次用不用 |
|---|---|---|---|
| **CH1~CH10** | CH1…CH10 | 每通道输出 PWM（接舵机/电调） | ❌ 不用 |
| **数据口** | `i-BUS` / `S.BUS` / `DATA` | **串行数据输出**（iBus 或 SBUS，由 Output Mode 决定） | ✅ **就用它** |
| **BIND** | `BIND` / `B/VCC` | 对码用（短接后上电进入对码） | ✅ 对码时短接 |
| **SENS** | `SENS` | 接电压/高度等传感器 | ❌ 不用 |
| 电源 | 任意 CH 口的 `+ −` 或标注 VCC | 给接收机供电 | ✅ 接 5V/GND |

### 对码（对频 / Bind）步骤

> 一个接收机只能记住一台遥控器；换遥控器、换模型都要重新对码。

1. **遥控器关机**
2. 用**跳线帽（或杜邦线）**把接收机的 **BIND 针脚短接**
   （iA10B 上是标 `BIND` 的两针，常见是 BIND 与相邻的 VCC 或 GND 短接，看丝印）
3. 给接收机**通电**（接到板子 P1 座的 5V + GND，或 BEC）
   → 接收机 **红灯快闪** = 进入对码模式
4. **按住遥控器的 BIND KEY 不放**（i6X 的 BIND 键在机身背面/侧面的小按钮），
   然后**打开遥控器电源**
   → 屏幕显示绑定中
5. 几秒后接收机**红灯由快闪变为常亮** → **对码成功**
6. 松开 BIND KEY，**遥控器、接收机都断电**
7. **拔掉 BIND 跳线**（重要！不拔会一直停在对码模式）
8. 重新上电 → 红灯**常亮** = 正常连接；若红灯慢闪/快闪 = 没连上，重做一遍

### 对码成功后，再改输出模式

对码完成后才能通过遥控器写接收机设置：
`RX Setup → RF Standard = AFHDS 2A → Output Mode = S.BUS`

### 常见坑

| 现象 | 原因 |
|---|---|
| 红灯一直快闪 | 没对上码；或 BIND 跳线没拔（一直在对码模式） |
| 对码时遥控器没反应 | BIND KEY 没按住就开机了；或接收机没供电 |
| 数据口没信号 | Output Mode 没切成 S.BUS（默认可能是 PWM） |
| 板子收不到 | S/+/− 接错；或把正逻辑的 iBus 接到已反相的 P1 座 |
| 一动摇杆就重启 | 5V 供电不足（接收机要用 5V，别用 3.3V） |

## 三、遥控器设置（FS-i6X → SBUS）

1. 开机 → 长按 **OK** 进入系统菜单 → **RX Setup（接收机设置）**
2. **RF Standard** → 选 **AFHDS 2A**（iA10B 是 AFHDS 2A；若显示 AFHDS 需切）
3. **Output Mode（输出模式）** → 选 **S.BUS**
   - 若菜单里只有 `PWM / PPM`（旧固件），说明当前固件不支持 →
     要么刷 i6X 的 10 通道固件，要么退回 iBus 方案（`RC_PROTOCOL=0` + J8 座）
4. 退出保存

**对码（Bind）**：
1. 接收机插 **BIND 跳线**（或按住对码键）后上电 → 红灯快闪
2. 遥控器按住 **BIND KEY** 开机 → 红灯常亮 = 成功
3. 断电、拔 BIND 线，重新上电 → 红灯常亮 = 已连接

**失控保护 Failsafe（强烈建议设置）**：
菜单 → **Failsafe** → 设为 **OUT（无输出）** 或全部通道中位。
这样关遥控后：
- 接收机 SBUS 帧里的 **failsafe 标志位置位** → 板子**立即**判定失联（比等 100ms 超时更快）
- 或接收机停止输出 → 100ms 超时保护兜底

两道保险都在代码里（`rc_ibus.c` 解析 SBUS 的第 24 字节 flags：bit2=丢帧，bit3=失控）。

## 四、上电与串口验证

串口（**UART5 = PC12 发送，115200**）上电应看到：

```
==== GM6020 CAN demo (F405 + FreeRTOS) ====
clock source : HSE 25000000 Hz
...
BMI088 self-test:
  acc  CHIP_ID = 0x1E (expect 0x1E) : OK
  gyro CHIP_ID = 0x0F (expect 0x0F) : OK
  gyro self-test reg = 0x02 : OK
  acc magnitude = 1.0xx g : OK
BMI088 self-test PASSED
```

**确认遥控收到数据**（Keil Debug Watch 加 `g_rc`）：
- `frameCount` 持续增长（iBus 约每 7ms 一帧 → 每秒 ~140）
- `ch[0..3]` 在 1000~2000 之间，摇杆动时跟着变
- `linked = 1`

## 五、遥控控制电机（验收项 1）

```
rc 1            ← 串口命令：开启遥控控制（默认关闭，安全）
```

| 操作 | 期望 |
|---|---|
| 右摇杆**上下**推（CH2） | 电机按摇杆量**正/反转**（速度环，最大 ±250rpm） |
| 摇杆回中 | 电机停（速度目标 0，带 5% 死区） |
| 摇杆推到底 | 接近 250rpm（受 `ls` 限速） |

**可选安全开关**：
```
rsw 5      ← 用 CH5（SwA 拨杆）作为使能开关：拨到上位才允许输出
rsw 0      ← 取消开关
```

## 六、遥控保护测试（验收项 2）

| 操作 | 期望现象 |
|---|---|
| **关闭遥控器电源** | 0.1 秒内串口打印 `[RC] link lost -> motor disabled`，**电机立即没力**（停止发电压指令 / 发 0 电压） |
| 重新开遥控器 | 自动恢复（S1/开关条件满足后继续可控） |
| 拔掉 iBus 信号线 | 同上，立即停机 |
| 电机反馈 CAN 线拔掉 | 另一路保护：`online=0` → 立即停输出 |

**为什么能做到"没力"**：控制任务每 1ms 发一次电压指令；保护触发后
① 切 `MODE_IDLE` ② 清 PID 积分 ③ 发 **0 电压**，电机不再有驱动力矩（自由状态）。

## 七、IMU（BMI088）说明

- 原理图确认：BMI088 的 **PS 脚接地 = 强制 SPI 协议**，且只连了 SPI1（PA5/PA6/PA7）+ 独立片选
  → 本板**硬件上就是 SPI**，板上 I2C1(PB6/PB7) 只挂了 24C02 EEPROM。
- BMI088 / ICM-42688 **均无 DMP**（DMP 是 InvenSense MPU6050 / ICM-20948 系列专属）。
- 本阶段交付：**上电三重自检 + 原始六轴输出**（加速度 g / 角速度 °/s / 温度）。
  姿态解算（互补滤波）下次迭代补，阶段二已有 `attitude.c` 可直接移植。

自检内容（串口会打印）：
1. 加速度计 CHIP_ID = 0x1E
2. 陀螺仪 CHIP_ID = 0x0F
3. 陀螺自检寄存器流程（GYRO_SELF_TEST = 0x3C）
4. 静止时加速度矢量模长 ≈ 1g（板子要放平、别动）

## 八、故障排查

| 现象 | 检查 |
|---|---|
| `frameCount` 不涨 | ①接线是否接在 J8/PC7（不是 P1）②接收机是否对码成功（红灯常亮）③遥控器输出模式是否为 i-BUS ④共地 |
| 通道值乱跳 | 波特率/校验不对（应 115200 8N1）、或接到了反相的 DBUS 口 |
| 电机不转（遥控有数据） | 发 `rc 1` 了没？`rsw` 开关通道是否设了但拨杆没在上位？`ls` 限速是否太小？ |
| 关遥控电机还转 | 检查 `RC_LINK_TIMEOUT_MS`（100ms）；确认串口打印了 `link lost` |
| BMI088 自检失败 | 看哪一项 FAIL；CHIP_ID 失败 = SPI 接线/片选问题（原理图 CS_Accel=PC4、CS_Gyro=PA4） |
| 加速度模长不≈1g | 板子没放平或正在晃动，放平重跑 `imust` |
