# 第一部分：CAN 通信理论

## 1.1 为什么机器人上都是 CAN，而不是 I2C / SPI / 串口

| 对比项 | CAN | I2C | SPI | RS485 |
|---|---|---|---|---|
| 物理层 | **差分**（CAN_H - CAN_L） | 单端 | 单端 | 差分 |
| 拓扑 | 多主总线（挂 N 个节点） | 多主总线 | 点对点（片选） | 总线 |
| 抗干扰 | 强（差分 + 位填充 + CRC + 重发） | 弱 | 弱 | 强 |
| 错误处理 | **硬件自动重传 + 错误计数 + 自动离线** | 无 | 无 | 无 |
| 距离/速率 | 1Mbps@40m，5kbps@10km | 板级 <1m | 板级 | 长 |
| 仲裁 | **非破坏性逐位仲裁** | 有（时钟同步） | 无 | 需软件 |

一句话：**CAN 是"为恶劣电磁环境和多节点实时控制而生的差分总线"**，
电机驱动、汽车、机器人关节全都用它。

## 1.2 物理层（看得见摸得着的部分）

- 两根线：**CAN_H** 与 **CAN_L**，靠**电压差**表示位：
  - **显性（Dominant）= 逻辑 0**：CAN_H≈3.5V，CAN_L≈1.5V，压差 ≈ 2V
  - **隐性（Recessive）= 逻辑 1**：两线均 ≈2.5V，压差 ≈ 0V
- **"线与"规则**：总线上只要有一个节点发显性，总线就是显性 → **这是仲裁和 ACK 的物理基础**。
- **终端电阻 120Ω ×2**：总线两端各一个，消除信号反射。
  GM6020 内部电阻由**拨码开关第 4 位**控制（ON = 接入）；板端一般由收发器自带或跳线。
  实测：不上电时用万用表量 CAN_H-CAN_L 应约 **60Ω**（两个 120Ω 并联）；若 120Ω 说明只接了一个，若开路说明都没接。
- 电平由 **CAN 收发器**（如 TJA1050）转换：MCU 侧是 TXD/RXD（3.3V），总线侧是 CANH/CANL。

## 1.3 帧结构（标准数据帧，11 位 ID）

```
SOF │ ID(11bit) │ RTR │ IDE │ r0 │ DLC(4bit) │ DATA(0~8B) │ CRC(15) │ ACK │ EOF
 1  │    仲裁   │     │     │    │   长度     │             │  校验   │     │  7
```

- **SOF**：1 位显性，帧开始 + 硬同步。
- **ID（11 位）**：既是"名字"也是**优先级**（值越小优先级越高）。
- **RTR**：0=数据帧，1=遥控帧（要数据）。
- **IDE**：0=标准帧（11 位 ID），1=扩展帧（29 位 ID）。
- **DLC**：数据长度 0~8 字节。
- **CRC**：15 位校验 + 界定符。
- **ACK**：发送方发隐性，**任何接收正确的节点拉成显性**——发送方没收到 ACK 就会报错并重发（这是"没人应答就会一直重发"的原因）。
- 另外还有：**错误帧**、**过载帧**、**帧间隔**。

> GM6020 用的全是：**标准帧、数据帧、DLC=8、1Mbps**。

## 1.4 仲裁机制（面试高频）

多个节点同时发：每个节点边发边听。
- 发隐性(1) 但听到显性(0) → 说明**别人优先级比我高** → **立即停发，转入接收**，不发错也不破坏别人。
- 因此是 **非破坏性仲裁**（CSMA/CD+AMP）：**ID 小的帧天然先走**，靠硬件保证，无需软件。

**工程含义**：把"最要紧的帧"放到小 ID 上。DJI 的反馈 ID 0x205~0x20B 天然比控制帧 0x1FF/0x2FF 大（优先级低），这是 DJI 的设计选择——控制帧优先。

## 1.5 位时序（波特率怎么算出来的）

一位时间被切成若干 **TQ（Time Quantum）**：

```
  SYNC_SEG(1TQ) │ PROP+PHASE1 (BS1) │ PHASE2 (BS2)
                └────── 采样点在这里 ──────┘
```

公式（STM32 bxCAN）：

```
Baud = PCLK1 / (Prescaler × (1 + BS1 + BS2))
```

**本工程（F405，PCLK1 = 42MHz，目标 1Mbps）**：

```
42MHz / (3 × 14) = 1.0 Mbps
→ Prescaler = 3，BS1 = 10，BS2 = 3，SJW = 1
→ 采样点 = (1+10)/14 ≈ 78.6%  （推荐 75%~80%）
```

- **SJW（再同步补偿宽度）**：各节点晶振有偏差，靠它微调，一般取 1。
- **采样点太靠前**易受毛刺干扰，**太靠后**对传播延迟敏感——75%~80% 是工程经验值。
- **位填充**：连续 5 个相同位后自动插入一个反位，保证有足够的边沿来同步（也是错误检测手段之一）。

## 1.6 错误处理（为什么 CAN 很可靠）

5 种错误检测：**位错误、填充错误、CRC 错误、格式错误、ACK 错误**。

每个节点有 **TEC（发送错误计数）/ REC（接收错误计数）**：

| 状态 | 条件 | 行为 |
|---|---|---|
| 错误主动 | TEC < 128 | 正常，出错发"主动错误帧"（6 个显性位，强制打断） |
| 错误被动 | TEC ≥ 128 | 出错发"被动错误帧"（隐性），不能强制打断别人 |
| **Bus-Off** | TEC ≥ 256 | **自动离线**，不再收发（需软件或硬件恢复） |

> **实战提示**：单节点自测时没有其它节点 ACK，会一直重发并快速进入 Bus-Off——
> 这是正常现象，接上真实节点（电机）后即消失。CAN->ESR 的 LEC=3 就是 ACK 错误。

## 1.7 STM32 过滤器（过滤什么、怎么配）

总线上帧很多，只把想要的放进 FIFO。两种模式：

- **掩码模式（Mask）**：`ID & Mask == FilterId & Mask` 的通过。
  收全部 GM6020 反馈（0x205~0x20B）：FilterId=0x200，Mask=0x7F0（高 7 位必须匹配）。
- **列表模式（List）**：列举具体 ID，精确但数量有限。

建议：电机项目用**掩码模式**一次收 0x200~0x20F，后面加电机不用改过滤。

# 第二部分：GM6020 电调速查（来自官方手册 v1.4）

## 2.1 关键参数（务必记住，调参要用）

| 项目 | 数值 |
|---|---|
| 额定电压 | **DC 24V**（XT30 接口） |
| 通信 | CAN **1Mbps**（红=CAN_H，黑=CAN_L）；也支持 PWM |
| **最大空载转速** | **320 rpm**（⚠️ 见下方红字） |
| 额定扭矩 / 堵转扭矩 | 1.2 N·m / 0.86 N·m |
| 额定电流 / 堵转电流 | 1.62 A / 0.90 A |
| 转矩常数 | 741 mN·m/A |
| 极对数 | 10 |
| 定位精度 | 0.05° |
| 机械角度反馈 | **0~8191**（8192 刻度 = 一圈） |
| 反馈速率 | **1 kHz**（1ms 一帧） |
| 转向定义 | 从输出轴端看 **CCW（逆时针）为正** |

> ⚠️ **重要冲突**：任务书写"速度 1000rpm"，但 **GM6020 最高只有 320rpm**，物理上做不到。
> 1000rpm 是 **M3508（C620 电调）** 的转速量级（C620 反馈的是**转子**转速）。
> 若用 GM6020，建议把速度环目标改成 **60~200 rpm** 演示（或 300rpm 接近满速），
> 并在报告里注明"GM6020 受 320rpm 上限约束"。**这点需要你确认后再定最终目标值。**

## 2.2 指示灯速查（验收项重点）

| 颜色 / 闪烁 | 含义 | 该做什么 |
|---|---|---|
| **绿灯每 1 秒闪 N 次** | 正常，**当前 ID = N** | 这就是"辨识 ID"的方法 |
| 绿灯慢闪 | PWM 通信正常 | CAN 模式不会常出现 |
| 绿灯常亮 | PWM 行程校准中 | — |
| **橙灯每 1 秒闪 1 次** | 电机高温警告（>100℃） | 降负载 / 散热 |
| **橙灯每 1 秒闪 2 次** | **总线上有相同 ID 的设备** | 改拨码，避免 ID 冲突 |
| 橙灯每 1 秒闪 3 次 | PWM 信号无法识别 | — |
| 橙灯每 1 秒闪 4 次 | 温度传感器异常 | — |
| 橙灯常亮 | 电流控制模式下收到电压指令 | 模式不匹配，检查指令 ID |
| **红灯每 1 秒闪 1 次** | **供电电压过高** | 检查电源（必须 24V） |
| **红灯每 1 秒闪 4 次** | **电机温度过高（>125℃）** | 立即停机冷却 |

规则：异常优先于警告显示；多个同类同时存在时按**闪烁次数最少**的那个提示。
异常状态下**驱动器关闭输出**（电机没力）——所以"电机不转"先看灯。

## 2.3 ID 与拨码开关

拨码 **第 1~3 位 = ID 的 Bit0/Bit1/Bit2**（ON=1），**000 无效**：

| Bit[2:0] | 001 | 010 | 011 | 100 | 101 | 110 | 111 |
|---|---|---|---|---|---|---|---|
| 电机 ID | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| **反馈报文 ID** | 0x205 | 0x206 | 0x207 | 0x208 | 0x209 | 0x20A | 0x20B |

**第 4 位 = CAN 终端电阻**（ON = 接入 120Ω）。

**改变 ID 的操作**：断电 → 拨码开关改 Bit0~2 → 上电 → 绿灯每秒闪 N 次确认 N = 新 ID。
（注意：只有总线末端设备才把终端电阻拨到 ON。）

## 2.4 控制指令（MCU → 电机）

| 标识符 | 用途 | 数据域（8 字节） |
|---|---|---|
| **0x1FF** | **电压控制 ID1~4** | [0][1]=ID1 电压, [2][3]=ID2, [4][5]=ID3, [6][7]=ID4 |
| **0x2FF** | 电压控制 ID5~7 | [0][1]=ID5, [2][3]=ID6, [4][5]=ID7, [6][7]=无效 |
| 0x1FE | 电流控制 ID1~4 | 同上结构（需新固件 + Assistant 开电流环开关） |
| 0x2FE | 电流控制 ID5~7 | 同上 |

- **电压给定范围：-25000 ~ +25000**（int16，**大端：高 8 位在前**）
- 电流给定范围：-16384 ~ +16384（对应 ±3A）
- 一条指令最多控 4 个电机；**不用的槽位写 0**（写 0 = 该电机输出 0，但注意会覆盖上一次的值）
- 默认电压模式（电流模式需要固件 ≥1.0.11.2 且用 RoboMaster Assistant 打开电流环开关）

## 2.5 反馈报文（电机 → MCU，1kHz）

标识符：**0x204 + 电机ID**（ID1 → 0x205，ID5 → 0x209）

| 字节 | 内容 | 换算 |
|---|---|---|
| DATA[0..1] | 机械角度 | 0~8191 → 角度 = raw / 8192 × 360° |
| DATA[2..3] | 转速 | **int16，单位 rpm**（正=CCW） |
| DATA[4..5] | 实际转矩电流 | int16，-16384~16384 → ±3A |
| DATA[6] | 电机温度 | 单位 ℃ |
| DATA[7] | Null | — |

同样的：**高 8 位在前（大端）**，例如 `angle = (data[0]<<8) | data[1]`。

## 2.6 接线（云台板 ↔ GM6020）

| 云台板（F405） | GM6020 | 备注 |
|---|---|---|
| PA12 (CAN1_TX) | — | 接板载收发器 TXD |
| PA11 (CAN1_RX) | — | 接板载 RXD |
| 板载 CANH | **红**线 | 双绞线 |
| 板载 CANL | **黑**线 | 双绞线 |
| 24V 电源（XT30） | XT30 口 | ⚠️ 24V 强电，先确认极性再上电 |
| GND | 电源 GND | **必须共地** |

上电前用万用表确认：CANH-CANL ≈ 60Ω（两端终端电阻齐全），24V 极性正确。
